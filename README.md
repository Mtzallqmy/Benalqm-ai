# moataz ai

**منصة وكلاء ذكاء اصطناعي شاملة، ثنائية اللغة، مبنية فوق نواة DeerFlow مع الحفاظ على قدراتها الأصلية وتطوير تجربة مستقلة خاصة بـ moataz ai.**

> هذا المستودع هو تطوير مباشر للمشروع الأصلي **ByteDance DeerFlow** وليس إعادة بناء منفصلة لفكرته. نحتفظ بالنواة والـbackend والـskills والبنية التشغيلية الأصلية قدر الإمكان، ونضيف فوقها هوية moataz ai، واجهة عربية/إنجليزية، تجربة جوال، إدارة مزودات ونماذج ديناميكية، وتطبيق Android.

## ما هو moataz ai؟

moataz ai سيحافظ على منظومة DeerFlow الأصلية، بما فيها:

- Lead Agent وSub-Agents.
- Skills والأدوات القابلة للتوسعة.
- MCP integrations.
- الذاكرة طويلة المدى.
- Sandbox وتنفيذ الأوامر والتعامل مع الملفات.
- البحث والتصفح والـArtifacts.
- المحادثات والـThreads والمهام المجدولة.
- واجهة Web وGateway وواجهات API الحالية.

وتُضاف فوقها طبقة منتج مستقلة تشمل تدريجيًا:

- هوية بصرية ورسومية ولونية خاصة بـ **moataz ai**.
- واجهة عربية وإنجليزية كاملة مع دعم RTL/LTR.
- تجربة Mobile-first وتنقلات وانتقالات حديثة.
- تطبيق Android يحافظ على نفس قدرات الـbackend والـskills.
- إدارة مزودات الذكاء الاصطناعي بنمط BYOK: المستخدم يضيف API Key وBase URL الخاصين به.
- اكتشاف النماذج المتاحة للمفتاح تلقائيًا واختبار توافقها مع قدرات الوكيل قبل استخدامها.
- دعم OpenAI-compatible gateways مع adapters أصلية عند الحاجة لـOllama وvLLM وغيرهما.
- تشغيل محلي عبر Docker مع إمكانية ربط نماذج محلية أو مزودات سحابية.

## مبدأ التطوير

هدفنا هو **تطوير DeerFlow نفسه إلى moataz ai**، لا إنشاء مشروع آخر بجانبه.

لذلك نتبع قاعدة واضحة:

```text
Upstream DeerFlow core
        │
        ├── backend / harness / runtime / tools / skills
        │   نحافظ عليها بلغاتها وبنيتها الأصلية قدر الإمكان
        │
        └── moataz ai product layer
            ├── Brand system
            ├── Arabic + English UX
            ├── Mobile experience
            ├── Provider manager
            └── Android shell
```

الأسماء الداخلية مثل `deerflow` لا يتم تغييرها عشوائيًا في هذه المرحلة؛ ذلك يقلل التعارضات عند استيعاب تحديثات المشروع الأصلي ويحافظ على سلامة الاختبارات والاستيرادات البرمجية.

## التقنيات الحالية

نحافظ على التقنيات الأصلية للمشروع في أجزائه الموروثة، ومن أبرزها:

- Python 3.12+ للـbackend والـagent harness.
- FastAPI للـGateway.
- LangChain وLangGraph لبنية الوكلاء.
- Next.js 16 وReact 19 للواجهة.
- TypeScript للواجهة والتطويرات الجديدة الخاصة بالمنتج حيث يناسب.
- Tailwind CSS 4 ونظام المكونات الموجود في المشروع.
- Docker للتشغيل والعزل المحلي.

أي تقنية جديدة ستُضاف فقط عندما تحل حاجة فعلية بدون إعادة كتابة أجزاء مستقرة من DeerFlow بلا داعٍ.

## التشغيل المحلي — خط الأساس الحالي

قبل إضافة معالج الإعداد الخاص بـmoataz ai، تبقى أوامر DeerFlow الأصلية هي المرجع التشغيلي للنسخة الحالية.

### الإعداد

```bash
git clone https://github.com/Mtzallqmy/Benalqm-ai.git
cd Benalqm-ai
make setup
make doctor
```

### Docker — الخيار المفضل للتجربة المحلية المعزولة

```bash
make docker-init
make docker-start
make docker-logs
```

بعد التشغيل تكون نقطة الدخول الموحدة افتراضيًا:

```text
http://localhost:2026
```

### التطوير المحلي

```bash
make install
make setup-sandbox
make dev
```

> سيتم تبسيط هذه التجربة في مراحل لاحقة لتصبح إعدادات المزود والنموذج والاتصال المحلي قابلة للإدارة من واجهة moataz ai نفسها.

## خارطة التطوير

ننفذ المشروع على مراحل منفصلة قابلة للمراجعة:

1. **الأساس والمصدر والهوية الهيكلية** — تثبيت النسخة الأصلية، التوثيق، attribution، وBrand layer.
2. **الهوية البصرية ونظام التصميم** — الألوان، typography، الشعار والأصول، الحركة والـdesign tokens.
3. **العربية والإنجليزية** — i18n كامل، RTL/LTR، ومراجعة كل شاشات التطبيق.
4. **إعادة بناء تجربة الواجهة** — navigation، workspace، المحادثة، artifacts، agents، skills، settings والجوال.
5. **Dynamic Provider Manager** — API Key + Base URL + اكتشاف النماذج + capability probing + تخزين آمن.
6. **التشغيل المحلي المتكامل** — Docker UX، Ollama، LM Studio، vLLM وOpenAI-compatible endpoints.
7. **Android** — PWA/TWA أولًا مع الحفاظ على frontend واحد وbackend واحد، ثم native integrations عند الحاجة.
8. **الاختبارات والتقوية الأمنية والإطلاق**.

التفاصيل التنفيذية موجودة في `docs/MOATAZ_AI_ROADMAP_AR.md`.
